# Yokota Jobs

横田基地（LMO 横田支部）の求人を毎週収集し、**英語要件・賃金・雇用形態で絞り込める PWA**。

日本語を母語としない人が自分で見られるよう UI は英語。iPhone のホーム画面に追加して使う想定。

## なぜ作ったか

一般の求人サイト（Indeed 等）は日本語ができる前提の求人が大半だが、**LMO の在日米軍従業員求人は
国籍要件がなく、語学要件として明示されているのは英語（TOEIC 等のスコア）**という構造になっている。

そこで「日本語ができないから無理」ではなく「**TOEIC 何点あれば何件応募できるようになるか**」を
実データで測ることを目的にした。

単発の検索では分からないので、**募集終了した求人も消さずに貯める**。
数年ためれば「年間どの職種が何件出るか」「どのスコア帯が市場の何割か」が見えてくる。

## 応募資格について（調査済み）

[LMO の FAQ](https://www.lmo.go.jp/recruitment/qanda.html) より:

- **基本労務協約（MLC）** — 合衆国軍隊の構成員・軍属・その家族**以外**なら国籍を問わない
- **諸機関労務協約（IHA）** — 合衆国人（二重国籍含む）**以外**なら国籍を問わない
- 外国籍の場合は**就労資格が必須**

求人票の備考欄にも「日本国籍の方以外の方は、有効な在留カード（"就労制限なし"の記載があるもの）」とある。
**日本人の配偶者等の在留資格は就労制限なし**なので該当する。

**英語能力は証明書が必須**（TOEIC・英検・TOEFL 等のコピー添付）。自己申告は不可。
ここが実務上の関門なので、TOEIC 受験が具体的なタスクになる。

日本語については LMO の求人票に定型の「日本語レベル」欄が**無い**。
このアプリは本文中に日本語への言及があるものだけフラグを立てる方式にしている。
フラグが無い＝日本語不要とは限らない（履歴書自体が日英両文）。

## 2つのソースを統合している

| ソース | 言語 | 得られるもの |
|---|---|---|
| **LMO 求人応募サイト** | 日本語のみ | 賃金・就業時間・応募方法など詳細 |
| **374 FSS 求人告知(PDF)** | 日英 | 公式英語職種名、**配属先の部隊**、LPL、**募集範囲** |

FSS 側でしか分からない重要な情報が2つある。

- **募集範囲** — 「在日米軍従業員のみ」の求人は外部から応募できない。
  これを知らないと応募不可の求人を数に入れてしまう
- **募集言語** — 事務・技術職は英語のみの告知、技能職は日英併記。
  収集時点では**英語のみの告知＝LPL 1〜4（英語が必要）と完全に一致**していた

## 構成

```
fetch_jobs.py   LMO の収集＋FSS の統合 → jobs.json
fetch_fss.py    374 FSS の英語版求人告知(PDF)を解析
jobs.json       蓄積データ。募集終了分も active:false で残る
index.html      PWA 本体（日英切替・3タブ）
manifest.json   ホーム画面追加用
sw.js           Service Worker（HTML とデータは network-first）
make_icon.py    アイコン生成（滑走路モチーフ）
.github/workflows/fetch.yml   毎週月曜 09:00 JST に自動更新
```

依存は `pypdf` のみ（FSS の PDF 解析用）。

### 画面

| タブ | 中身 |
|---|---|
| **求人 / Jobs** | 英語要件・募集言語・職種・雇用形態でフィルタ。外部応募可の求人のみ表示が既定 |
| **傾向 / Trends** | TOEIC スコア別の到達件数、募集言語の内訳、英語要件の分布、職種別、給与中央値 |
| **学習 / Study** | 英語学習用の YouTube 動画を貯めてアプリ内で再生 |
| **説明 / About** | 応募資格・募集言語の意味・日本語要件・出典 |

右上の **EN / 日本語** で表示言語を切り替えられる（選択は端末に保存される）。
日本語表示では日本語原文を、英語表示では公式英語名と英語原文を優先して出す。

Trends の「TOEICスコア別の到達件数」が中核。
スコアを上げると応募可能な求人が何件増えるかが一目で分かる＝学習目標の根拠になる。

### 学習タブ

YouTube の URL を貼るだけで動画を貯められる。`watch` / `youtu.be` / `shorts` /
`embed` / `live` / 生ID のどの形式でも解析する。タイトルと投稿者は
**oEmbed から取得**するので API キーは要らない。再生は `youtube-nocookie.com` の埋め込み。

カテゴリ（TOEIC / リスニング / 面接 / 基地の仕事 / その他）と視聴済みフラグで絞り込める。

**視聴リストは localStorage にだけ置いている。**
このリポジトリは公開しているので、個人の学習履歴がコミットに入らないようにするため。
端末をまたいだ同期はされない。

### 画像を載せていない理由

求人票に実際の職場写真は存在しない（LMO の求人票に画像なし、FSS の PDF もロゴ1枚のみ）。
イメージ写真で埋めると実態と無関係な印象を与えるので、代わりに
**配属先の部隊名**（374 Civil Engineer Squadron、DFAS/JRJD など）を出している。
これは実在する所属先で、写真より具体的な情報になる。

## 実行

```bash
python3 fetch_jobs.py                 # 通常
python3 fetch_jobs.py --no-translate  # 翻訳をスキップ（高速）
python3 fetch_jobs.py --limit 5       # 5件だけ（動作確認用）
```

macOS の python.org 版 Python で証明書エラーが出る場合:

```bash
YJ_INSECURE_SSL=1 python3 fetch_jobs.py
```

GitHub Actions（Ubuntu）では不要。

## 取得の仕組み

LMO の求人サイトは ASP.NET WebForms で、**詳細ページへの直接 GET は弾かれる**。

1. `oubo.lmo.go.jp/oubo_pub/keisai/` を GET してセッションと ViewState を得る
2. `cbYokotaSibu=on` で POST して横田支部の一覧を取得
3. カテゴリのチェックボックスを1つずつ立てて再検索し、整理番号 → カテゴリの対応表を作る
   （一覧にカテゴリ列が無いため）
4. 一覧の ViewState を使い回して `__EVENTARGUMENT=詳細$N` を POST → 各求人の詳細
5. `lbl*` の span id から項目を抽出

ViewState は再利用できるので、詳細は **1求人1リクエスト**で済む。
公的機関のサイトなのでリクエスト間隔は 1.2 秒あけている。

### 抽出している主な項目

| 項目 | 抽出元 |
|---|---|
| 英語要件（語学能力級レベル / TOEIC 点） | 必要な免許資格等 |
| 月給（基本給＋地域手当）/ 時給 | 賃金 |
| 契約種別（MLC / IHA / 時給制） | 整理番号3文字目（M / I / H） |
| カテゴリ | カテゴリ別検索の結果 |
| 日本語への言及 | 仕事の内容・必要な免許資格等 |

## 注意

- サイト構造が変わると壊れる。求人0件になったら例外を投げて気付けるようにしてある
- 翻訳は Google の非公式エンドポイント。失敗したら原文表示にフォールバックし、次回再試行する
- 賃金が「備考欄参照」の求人は金額を抽出できない（詳細に原文が出る）
